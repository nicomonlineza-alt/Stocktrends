# Stocktrends — Build Status and Next Steps

## Current milestone: dashboard foundation

The repository contains a Vite + React single-page application.

### Implemented in the current prototype
- Responsive dashboard layout for desktop and mobile.
- Five illustrative Nasdaq candidates with sample prices, daily moves, scores and selection notes.
- Browser-local paper-trading interactions and a simulated portfolio ledger.
- Performance summary and trade history.
- Company/market research links.
- Explicit disclosure that market values are sample data, not live quotes.
- No broker connection and no real-money order execution.

### Limitations to keep visible
- The current price and score values are hard-coded demo values.
- The selection is not yet generated by a trained AI model or verified market data.
- Browser-local storage is tied to the current browser/device; it is not a shared database.
- Simulated returns on sample prices do not demonstrate that a strategy is profitable.

## Build sequence

### Phase 1 — Dashboard foundation
- [x] React/Vite project structure.
- [x] Five-stock dashboard and candidate list.
- [x] Paper-trading interface and local ledger.
- [x] Responsive visual styling.
- [ ] Build/test verification and interaction review.

### Phase 2 — Market data
- [ ] Connect Twelve Data through a server-side endpoint.
- [ ] Keep API credentials in server environment variables; never expose secrets in browser code or Git.
- [ ] Display quote timestamps, market session, currency and stale-data/error states.
- [ ] Confirm subscription limits and whether the selected feed is real-time or delayed.

### Phase 3 — Daily pick discipline
- [ ] Fix and document the eligible Nasdaq universe.
- [ ] Lock exactly five selections per trading day with a timestamp and reference price.
- [ ] Prevent re-generation from silently replacing historical selections.
- [ ] Version each selection method and store its inputs.

### Phase 4 — Evaluation and learning
- [ ] Store picks and outcomes in a database.
- [ ] Calculate directional accuracy, simulated P/L, win rate and drawdown.
- [ ] Compare results to a transparent baseline.
- [ ] Use chronological out-of-sample testing and avoid future-data leakage.
- [ ] Include realistic spread, fees, slippage and currency-conversion assumptions.

### Phase 5 — Deployment
- [ ] Verify production build.
- [ ] Configure server-side environment variables securely.
- [ ] Deploy to Vercel only after the GitHub prototype has been reviewed.

## Non-negotiable project rules
1. Paper trading only; no live broker orders.
2. Never present demo values as live market data.
3. Never promise profit or call an unvalidated score a probability.
4. Preserve historical picks and results instead of rewriting the past.
5. Build in small increments and keep the repository as the source of truth.
